# distill · 蒸馏书籍与长内容

一个 Agent Skill（Claude Code 等支持 `SKILL.md` 的工具可用）。把整本书、长文与报告、课程或音视频逐字稿、一批同主题材料，做成两种东西之一：

- **精华摘要**：读完可以不读原文，每一句都能回到原文核对。
- **一个 skill**：把材料里的方法变成 AI 能照着做的规则，装上就能用。

开始时它会先问你要哪一种（话里已经说清就不问）。它不依赖任何其他 skill。

它和常见的「AI 读书摘要」差在三件事：

1. **引文和出处由脚本回查。** 引号里的每一句原话，脚本会去原文里逐字找，并核对它是不是在标注的那一页、那一行、那个时间点。找不到的不许加引号。
2. **三层分开标。** 原书说的（带出处）、整理者把几处合起来的概括（标 `【归纳】`）、整理者自己的判断（单独的「评注」块），读者一眼分得清，不会把整理者的话当成作者的话。
3. **不拿模型的记忆冒充读过的内容。** 只给书名时，它先联网找公开材料并存盘，按拿到的材料定等级，材料不够就少写；没存盘的网页不算来源，被抓取工具概括过的内容不能当引语。

## 能处理什么

| 你给的 | 它怎么做 |
|---|---|
| 文件：PDF、EPUB、DOCX、TXT、Markdown、HTML、字幕（SRT、VTT） | 抽出带页码、行号或时间标记的文本，分批通读 |
| 扫描版 PDF | 用 macOS 自带的文字识别在本机 OCR，不联网 |
| 一批材料 | 各自做底稿，再按话题对照：一致、互补、冲突分别标出，冲突的并列不调和 |
| 只有书名 | 联网找目录、试读、作者访谈、严肃书评，存盘后定材料等级（T1 原文在手 / T2 部分原文 / T3 仅二手），等级决定能写哪些板块 |

摘要的产出是 `digest.md` 和一个双击就能打开的 `digest.html`。做 skill 的产出是一个 skill 包文件夹（`SKILL.md` 加规则文件，每条规则带原书页码），不会自动安装，复制到你的 skill 目录就能用。

## 安装

把整个仓库放进 skill 目录即可：

```bash
git clone https://github.com/app0922121/distill-skill.git ~/.claude/skills/distill
```

依赖：Python 3.9 以上（只用标准库）。读 PDF 需要 `pdftotext`（poppler，macOS 上 `brew install poppler`）。扫描版 OCR 只支持 macOS。

装好后直接说话就行：

- 「帮我把这本 PDF 蒸馏一下」
- 「这个三小时的课程逐字稿帮我提炼成方法」
- 「《某本书》帮我拆一下，我没有电子版」
- 「把这三份行业报告合起来提炼要点，标清出处」
- 「把这本书做成一个 skill，我想让 AI 照着里面的方法帮我分析」

## 不能跑脚本的地方：两段便携版 prompt

- [`assets/portable-prompt.md`](assets/portable-prompt.md)：做摘要。
- [`assets/portable-prompt-skill.md`](assets/portable-prompt-skill.md)：把书或文章做成 skill，产出一个 `SKILL.md` 和一份规则文件的完整内容。

都是可以整段复制的 prompt，贴到网页版 Claude、ChatGPT、豆包等工具里，再把材料贴在后面。它没有脚本核对，靠「先摘原话再归纳」和末尾的自查表来约束，重要的引文仍建议自己回原文看一眼。

## 它是怎么工作的

两段式：先分批读原文、抄下带出处的底稿，再只从底稿写成品，最后回原文核对。

| 步 | 做什么 | 产物 |
|---|---|---|
| 0 接单 | 登记材料，检查抽取质量，定材料等级 | `manifest.json`、`text/` |
| 1 地图 | 读目录、序言、结语和各章首尾，写全书地图，给章节分类 | `map.md`、`chapters.json` |
| 2 抽底稿 | 每批带着地图读原文，先抄原话再写转述，逐条挂出处 | `notes/` |
| 3 核底稿 | 脚本查引文、查章节覆盖 | `verify/` |
| 4 写成品 | 只看地图和底稿写 | `digest.md` |
| 5 核成品 | 脚本核对；另派一个没参与写作的核对者逐条回原文；再派一个只读成品的读者找读不懂的地方 | `verify/` |
| 6 交付 | 渲染成网页 | `digest.html` |
| 7 做成 skill（选了才做） | 列出材料里所有能照做的方法 → 写成带出处的规则 → 组装 skill 包（含输出格式和示例）→ 脚本检查、另派人核对规则、试用对比 | `skill-draft/<名字>/` |

三个脚本各管一件事：

- `scripts/prep.py`：把各种输入变成带定位标记的纯文本；网页材料抓取存盘；扫描版 OCR；排阅读批次。
- `scripts/verify.py`：引文逐字回查与位置校验、出处有效性、章节覆盖对账、成稿结构检查；`verify.py skill` 检查做出来的 skill 包。它只能证明「引号里的字在原文里、出处指的地方存在、每个核心章节有去向」，转述是否忠实要靠第 5 步的独立核对。
- `scripts/render.py`：把 `digest.md` 渲染成单文件网页，出处变成小标签，页脚如实写三道核对各自做没做。

细则在 `references/` 下，`SKILL.md` 里写明了每一步该读哪一份。

回归测试：

```bash
python3 tests/test_scripts.py
```

## 评测做到了哪一步

用一份约 1.9 万字的方法类材料做了四轮盲评：同一道题由「不用任何 skill 直接做」、本 skill、两个开源的同类 skill 各做一遍，匿名编号后交给两位评委，评委先读原文列要点，再按事先写定的检查项逐份回原文核对。

- 前两版没有过线：第一版出处过密、露出制作过程；第二版用「占原文百分之几」去压篇幅，把步骤和名目压没了，输给了直接做。
- 第三、四版两位评委都排第一。最后一版抽查的 15 条事实有 14–15 条完全有据（直接做的是 10–11 条），随机 10 句都能分清三层（直接做的是 7–9 句）。

「做成 skill」这个功能是后加的，验证得还不充分：第一次盲比时，我们做出的 skill 包规则更忠实，但覆盖和使用指引不如「不用 skill 直接做」的那个，两位评委都小幅偏向后者。之后针对这几点改了做法（先列方法清单、必须有输出格式和示例），还没有重跑验证。

要照实说明的限制：

- 只在这一份材料上做过完整盲评。**十万字以上的整本书、音视频逐字稿、多份材料合并、两段便携 prompt 都没有测过**，第一次用在这些场景时请当作试跑。
- 两个开源对手是按它们的说明文档手工执行的（没有跑它们的脚本），属于间接对比。
- 评委是 AI 子代理，每份只抽查 15 条事实和 5 个出处，不是全检。
- 要登录或靠脚本渲染的页面（多数在线试读）抓不到。只给书名时，结果常会停在较低的材料等级；自己把试读章节存成文件交给它，效果会好很多。

两条从评测里得到的教训，写进了规则：不用比例管详略，改看「作者编号列举的东西是否全部列出」；短材料不出和正文重复的板块。

## 不做的事

- 不下载、不代找在版书的盗版全文。公版书可以去合法来源取全文。
- 不为凑板块而写。某个板块没有材料支撑就不出。
- 成品供个人学习使用，引文单条尽量不超过一百字。

## 致谢

做这个 skill 之前读了约三十个同类实现和几篇论文，下面这些机制是从它们那里学来的（只借做法，文字和代码是自己写的）：

- 按手里的材料定等级、等级决定能出哪些板块：[book2note-skill](https://github.com/YMaxwellHayes/book2note-skill)、[ljg-skills](https://github.com/lijigang/ljg-skills) 的 ljg-book
- 引文逐字回查、核对与写作分开：[ohugonnot/claude-skills](https://github.com/ohugonnot/claude-skills) 的 book-distill
- 先建全书地图、覆盖审计、术语表三列、一本书不拆成一堆 skill：[cangjie-skill](https://github.com/kangarooking/cangjie-skill)
- 先验快照、全程只停一次确认：[nuwa-skill](https://github.com/alchaincyf/nuwa-skill)
- 把「模型记忆」单列为一类信息：[book-distiller-skill](https://github.com/AINoSleep/book-distiller-skill)
- 先摘原话再归纳：Anthropic 的长文档提示指南
- 整书摘要容易漏关键内容、模型自查靠不住：FABLES（Kim et al., 2024）、BooookScore（Chang et al., 2023）
- 先看全貌再读细节、看懂之前不评判：Adler《如何阅读一本书》
