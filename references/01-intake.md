# 01 · 接单、抽取质检、材料等级、只给书名

第 0 步读这份。`S` 指 `scripts/` 目录，`W` 指工作区。

## 1 建工作区并登记材料

```bash
python3 S/prep.py init W
python3 S/prep.py add W <文件> --title "书名"        # pdf / epub / docx / txt / md / html / srt / vtt
python3 S/prep.py add W <文件> --page-marker '<正则>'  # 纯文本里已有分页行时，把它们转成页码（见第 2 节）
python3 S/prep.py add W <文件> --ocr                  # 这份文本本身是 OCR 或自动转写出来的
python3 S/prep.py ocr W <扫描版.pdf>                 # add 报「多半是扫描版」时改用它（只支持 macOS，本机识别不联网）
python3 S/prep.py add-url W <网址> --kind <类型>     # 网页材料，类型见下文
python3 S/prep.py status W
```

其他入口先转成上面的格式再登记：

| 用户给的 | 先做什么 |
|---|---|
| 对话里直接贴的全文 | 原样存成 `W/in/pasted.txt` 再 `add` |
| 飞书文档链接 | 用本机的飞书文档 skill 导出成 Markdown 再 `add` |
| YouTube 等视频链接 | 有 `yt-dlp` 就取原语言字幕（`.vtt`）再 `add`；没有字幕就告诉用户，问要不要提供转写稿 |
| 音频、视频文件 | 需要先转写。本机有现成的转写工具就用；没有就告诉用户，不擅自安装 |
| 同一本书既有 PDF 又有 EPUB | 优先 EPUB（排版有语义、少错位）；要引页码时再登记 PDF |

登记前先看一眼文件开头几十行：有没有现成的分页行、是不是 OCR 文本。有就第一次登记时直接带上 `--page-marker` 和 `--ocr`，省得重登。OCR 文本里零星的页码残渣（如单独一行的 `5m`）脚本不会当成页眉跳过，夹在跨页句子中间时那一句就别引。

## 2 开工前先检查（不对就停下来告诉用户，别硬做）

| 现象 | 处理 |
|---|---|
| 文件是空的、打不开、格式不支持 | 说明原因，请用户换文件 |
| `add` 报「多半是扫描版」 | 改用 `ocr`；告诉用户 OCR 会有错字、图表里的字可能丢 |
| `add` 报「英文被拆成零碎字母」 | 抽看原页；换 EPUB 或换版本，实在没有就 `ocr` |
| `add` 报「有 N 处像分页行的内容」 | 纯文本里带着原书的分页行（如 `=== 第 24 页 ===`）。重新登记并加 `--page-marker`，正则里用括号抓页码数字，例如 `--page-marker '^=== 第 (\d+) 页 ===$' --id S1`。这样出处能写页码，读者可以拿去翻书；脚本还会标出每页重复的页眉，跨页的句子才能逐字核对上 |
| 用户给的文本本身就是 OCR 或自动转写的（成批错字、缺字） | 登记时加 `--ocr`；在地图的「材料状况」里记下典型错字 |
| 没有封面和版权页，读不到作者、版次 | 标题行写「所给材料未署名」；可以搜一次书目信息，用 `add-url` 落盘后再写作者和版本，并挂那个网页的锚。不凭记忆填 |
| 内容不足 300 字 | 确认是不是拿错了文件 |
| 明显缺页、只有前几章、是试读本 | 按实际拿到的范围做，材料等级降为 T2，并在成品开头写明 |
| 文件里混着两本书、或带大量广告页 | 在地图阶段把无关部分标 `skip` 并写原因 |

**抽取质检（整本书必做，三处各看一眼）**：打开 `W/text/<ID>.txt` 的开头、正中、结尾各一段，对照原文件看三件事：文字是否连贯；页码或时间标记是否和原件对得上；表格、多栏、脚注有没有搅在一起。发现问题记进 `W/map.md` 的「材料状况」一节，成品末尾的「关于这份解析」里要写。

**OCR 错字遇到引文怎么办**：优先引没有错字的句子。非引不可的那一句，照文本原样抄（错字也照抄，否则逐字核对过不了），紧跟着标 `〔存疑：OCR，疑为「某字」〕`，不要悄悄改字。

**版本**：把封面页或版权页上的版次、译者、出版年抄进 `map.md`。页码一律指「所给文件的第几页」，不是印刷页码；两者差值稳定时在成品末尾的「关于这份解析」里写一句换算关系（如「印刷页码 ≈ 文件页序 − 14」）。

## 3 材料等级：能写到什么程度，取决于手里有什么

| 等级 | 手里有什么 | 能出的板块 | 不能出的 |
|---|---|---|---|
| **T1 原文在手** | 用户给的全文，或合法取得的公版全文，并且**通读了** | 全部：速览、主体、术语、方法清单、引语、评注、规则库 | — |
| **T2 部分原文** | 可靠的结构（完整目录）＋至少一项实质文本：试读章节、作者本人的长文或长访谈、作者公开的配套资料（模板、讲义、练习）、逐章复述的长书评 | 速览、按目录搭的骨架、材料覆盖到的论点（每条挂网页锚）、评注；规则库只能出「草稿·未核原文」 | 页码；材料没覆盖到的章节内容；方法的细节步骤（材料里明确写了步骤的除外，并写清出自哪份材料） |
| **T3 仅二手** | 只有简介、电商页、短评、百科、别人的摘要 | 一页「线索版」：这是本什么书、各来源一致提到的主张（逐条挂锚并写「据某来源」）、获取原文的建议 | 引语、章节内容、方法步骤、规则库 |

规则：

- 等级写在成品第一屏（`材料等级：T2` 这一行脚本会查），不能只写在文末。
- 读到一半就动笔，等于拿 T2 的内容挂 T1 的牌子。T1 的前提是通读。
- 板块没有材料支撑就不出。**空着是正确结果，不是失败。**
- T2、T3 交付时主动告诉用户：给全文可以升到 T1，能多出哪些板块。

## 4 只给书名

用户只说了书名（或书名加作者），没给文件。目标是：合法地把能拿到的公开材料拿全，落盘，按上表定级，然后照常蒸馏。

### 4.1 先确认是哪本书

搜一次，确认书名、作者、出版年、有无多个版本或同名书。有歧义就列出候选让用户选，不要自己挑一本。译本和原版内容可能有删改，记下这次材料对应的是哪个版本。

### 4.2 先验快照

查资料之前，把自己对这本书已有的印象写进 `W/prior.md`：主旨是什么、分哪几部分、有哪些著名概念。开头写明「以下来自模型记忆，未核实，只用来想检索词，不得写进成品」。

对这本书没什么印象也照写，写你对这个题目的一般印象。

它有两个用处：把「记得的」和「查到的」在文件上隔开；搜集完以后对照它，记下被推翻、被加深、新增的各有哪些。几乎没有不同，说明搜到的还只是常识，要换更深的来源。

### 4.3 按这个顺序找

1. **合法全文**：公版书去古登堡计划、维基文库、中国哲学书电子化计划这类站点；作者或出版方自己公开的全文。找到就是 T1。
2. **结构**：出版方页面、图书馆书目、正规电商页上的完整目录。
3. **试读**：出版方或电商提供的试读章节、作者公开的节选。
4. **作者本人**：作者围绕这本书的长文、长访谈、演讲稿或演讲字幕。
5. **严肃长书评**：逐章复述并有评价的书评（报刊、学术期刊、有署名的专业博客）。
6. **批评与后续**：对这本书的主要批评、出版后被修正或被证伪的主张。评注层要用。没找到批评材料，在交付时说明。
7. **别人的摘要和笔记**：只用来发现线索、定位上面几类来源，**不单独当证据**。

检索词：书名加「目录」「试读」「作者 访谈」「书评」；中文搜不到时换原书名搜；全名搜不到时换书里独有的概念词加作者名。中英文各搜一轮。

### 4.4 每份要用的材料都落盘

```bash
python3 S/prep.py add-url W <网址> --kind 试读       # 脚本直接抓正文存成 W/text/W01.txt
```

`--kind` 可选：全文、试读、目录、作者访谈、作者文章、演讲、长书评、短评、简介、他人摘要、百科、其他。

- 脚本抓不到（要登录、靠脚本渲染、被拦）：换一种抓取方式拿到正文后，存成文件再登记：`add-url W <网址> --kind 长书评 --from-file page.txt`。
- 如果拿到的是抓取工具**概括过**的内容而不是页面原文，必须加 `--not-verbatim`。这种来源可以支撑转述，不能摘引语，脚本会拦。
- 登记错了、重复了、抓到的正文不能用的，用 `python3 S/prep.py remove W <ID>` 去掉，别让废来源留在清单里。
- 抓到的网页文本前后常带导航、页脚等杂项，读的时候跳过；底稿只从正文部分取。
- **没落盘的网页不算来源。** 只在搜索结果摘要里见过、没有打开读过的页面，不能挂锚。
- 视频用字幕文件登记（`add`），定位用时间点。

### 4.5 哪些来源降权或不用

- 不用：在版书的盗版全文和扫描件（搜到也不抓）；内容农场、机器生成的书摘站、「五分钟读完某某」。
- 只当线索：百科、别人的读书笔记、听书平台的讲书稿、问答站。
- 出版方文案可以收，但要认清它是宣传文案，不是正文。
- 搜到的全是同一作者的**其他**书：这不算找到了材料。
- 作者公开的配套资料不等于正文。成品里按它的本名称呼（「配套模板里写的是……」），不说「书中写道」。
- 一个网页里既有目录又有前言全文这类情况，`--kind` 按其中最有分量的那类选（有正文原文就选「试读」）；选错了用 `python3 S/prep.py set-kind W <ID> <类型>` 改。
- 多篇二手说法一致，不等于被证实，它们常常互相抄。一条主张要追到作者本人的文字或访谈才算数；追不到的，成品里写「据某书评」。

### 4.6 定级并告诉用户

按第 3 节的表定级。判据看材料的**种类**，不看数量：十篇短评仍是 T3，一章试读加完整目录就是 T2。

然后进流程的确认点，告诉用户：拿到了哪几类材料、定的是哪一级、哪些板块会关掉、给全文能多出什么。用户说过「直接做」就不等回复，按定好的等级往下做。

T2、T3 的后续流程照旧，只是「原文」换成落盘的网页材料：地图根据目录和已有材料来写；底稿和成品里的锚都是 `〔W03〕`（整份材料）或 `〔W03:L15〕`（材料文本的第 15 行）这一类，并列时每个都带来源编号：`〔W03:L15、W07:L40〕`。

T2 的 `chapters.json` 这样写：每份要通读的网页材料各占一条（`source` 写它的编号，行号从 1 到末行，`class` 按它的分量写 `core` 或 `support`，只当线索用的写 `skip` 并说明原因）；目录里有、但没拿到任何材料的章节也各列一条，只写 `{"id": "ch05", "title": "第五章 ……", "class": "nomaterial"}`，脚本会把它记成「无材料」。
