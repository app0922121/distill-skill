# 04 · 核对

第 3、5 步读这份。核对分三道，互相不能替代：机器查「字在不在、位置对不对、章节有没有去向」；独立核对者查「转述和归纳有没有走样」；只读成品的读者查「看不看得懂」。

写的人不审自己的稿。后两道必须交给没有参与写作的子代理；没有子代理时，另开一个干净的会话来做，至少也要隔开上下文，只带下面规定的材料。

## 1 机器核对

```bash
python3 S/verify.py quotes W      # 第 3 步：查底稿里的引文和锚
python3 S/verify.py coverage W    # 第 3 步：查每章有没有底稿、底稿是不是只落在章首
python3 S/verify.py all W         # 第 5 步：上面两项加成稿结构，一起查
```

报告存在 `W/verify/`。退出码 1 表示有必须处理的问题。逐项处理办法：

| 结果 | 意思 | 怎么办 |
|---|---|---|
| `MOVED` | 原话找到了，但不在锚指的位置 | 把锚改成报告给出的实际位置 |
| `NEAR` | 没逐字找到，有一句很像的 | 对照报告里的原文改成一字不差；或去掉引号改成转述。来源是 OCR 或字幕时可能只是识别差异，看一眼确认即可 |
| `FAIL` | 原文里找不到 | 先缩短成最有把握的半句再查一次；仍找不到就删掉引文，并检查这句话背后的内容到底有没有依据 |
| `BADSRC` | 引文出自登记为「非逐字」的来源 | 去掉引号改成转述，或找到页面原文重新登记 |
| `BADANCHOR` | 锚指向不存在的页、行或来源 | 改对；改不对说明这条内容来路不明，删 |
| 核心章没有底稿 / 只覆盖了一部分 | 没读或没读完 | 回去读完补底稿。不要为了过关随便补一条 |
| 核心章在成稿里没出现 | 成品漏了主线 | 写进去；确实不该写的，在 `chapters.json` 里加 `omitted_reason` 并写进成品末尾的「关于这份解析」 |
| 有内容不属于任何章节 | 章节表没铺满 | 补进 `chapters.json`，不要的标 `skip` 并写原因 |
| T2/T3 正文有无锚内容 | 没有来源的内容 | 找到来源并落盘挂锚；找不到就删，或挪进评注块并写明是整理者的看法 |
| T1 正文无锚的提醒 | 可能是过渡句，也可能是没依据的内容 | 过渡句并进相邻段落；有实质内容的补锚，补不出就删 |

报告里标「提醒（不计入必须处理）」的两类——有原文时个别块没有锚、锚偏密——不挡流程，但要逐条看过并处理或说明理由。篇幅比例只是参考数，不据此增删。

规矩：

- 标「✗」的问题清零才能进下一步。不许改脚本、改阈值来绕过检查。本来就不是引文的话（自拟的问句、自己的概括）误加了引号，去掉引号是改正，不算绕过。
- 每次核对的结果会追加到 `W/verify/history.jsonl`，交付时要报「中途改过几条」就看它。
- 改完成稿要重跑 `verify.py all`，再渲染。
- 机器通过只说明引号里的字和出处位置是对的。**转述歪了、归纳过头、轻重放错，机器查不出来。**

## 2 独立核对（查转述和归纳）

派一个核对者，只给它四样东西：成稿 `W/digest.md`、原文 `W/text/`、章节表 `W/chapters.json`、这份任务说明。**不给底稿，不给地图，不给写作时的任何解释。**

任务说明照这个意思写（另外告诉它三件事：原文文本里 `⟦p24⟧` 是页码标记、`⟦页眉 …⟧` 是每页重复的页眉，都不是正文；文本如果是 OCR 的，有错字，按能读出的意思判断；出处标签怎么对应到文本）：

> 逐条检查下面这份成稿里的陈述是否被原文支持。对每一条：按它句末的出处标签找到原文那一处，只读原文，判断原文是否说了这个意思。不要参考你自己对这本书的了解：即使某句话在现实里是对的，原文那里没有说，也判为不支持。
>
> 必查：一屏速览里的每一条（它是压缩得最狠的地方，要和正文对应的那一节、和原文都对一遍）；「如果只记三句话」的每一条；所有带【归纳】的句子；所有含数字、年份、专名的句子；所有说「因为……所以……」「导致」「证明」的句子。其余正文每节至少抽三条。
>
> 以「> [评注]」开头的块是整理者自己的看法，不查它是否被原文支持，但要查两件事：它有没有把自己的看法说成作者的意思；它里面引到的书中事实（数字、作者在哪里谈过什么）对不对。
>
> 每条给出：行号、判定（支持／部分支持／不支持／出处处查不到）、原文依据（抄一句）、问题说明。评注块里的事实出入单独计数。最后单列四类问题：把作者的推测写成结论的、把个别例子推广成普遍结论的、原文有重要限定条件而成稿漏掉的、正文里没有标记的整理者看法。
>
> 另外做两件事。第一，查「偏薄」：把原文里作者编号或逐条列举的地方（几个步骤、几条原则、几个要素、几条好处、图表里的各个部分）逐处列出来，看成稿是不是都列全了、每一项有没有说清是什么；成稿只写了数量、只举了其中几条、或只剩名字的，逐处记为「偏薄」。问自己一句：只拿着这份成稿，能不能照着做，还是得回原文？第二，对照 `W/chapters.json` 的章节表翻一遍原文各章，成稿有没有漏掉哪条明显的主线？有没有哪个次要内容被写得比主要内容还重？
>
> 结果写进 `W/verify/independent.md`，只回一行结论。

处理：

- 「不支持」「查不到」：改到被原文支持，或者删。改完重跑机器核对。
- 「部分支持」：多半是漏了限定条件或说得太满，照原文收紧。
- 「偏薄」：补全。编号列举的东西一条不少地列出来；补的内容先进底稿再进成稿。
- 评注块里的事实出入：和正文一样改。
- 判为支持但附了意见的：属实就改，不必等它被判成「部分支持」。
- 被指出的漏项和轻重问题：回底稿和原文确认后再改，不是核对者说什么就改什么。漏的是主线，必须补；漏的是次要内容，可以不补，理由写进交付汇报。「成稿已经太长」不能当作不补主线的理由，那说明别处该删。
- 改的时候新写进成稿的内容，同步补一条底稿，保持「成品里有的，底稿里都有」。
- 改动的句子超过五句时，再派一次核对，只查改过的句子。

整本书条目很多时，核对者可以按成稿的章节分成几个并行，各查一部分。

## 3 只读成品的读者（查读不读得懂）

再派一个读者，**只给成稿**，不给原文和其他任何东西（把成稿单独拷到一个空目录再给它，免得它顺手读到底稿）。请它：

1. 用三五句话复述：这本书要解决什么问题、答案是什么、靠什么站住。
2. 指出读到哪里卡住了：没解释就出现的词、跳了一步的推理、看不出和前文关系的段落。
3. 指出哪些地方分不清是作者的意思还是整理者的意思。
4. 说说读完以后，哪些内容能直接拿去用，哪些只是知道了。

它的回答由你存成 `W/verify/reader.md`（它只拿到成稿，不进工作区）。

两道核对意见相反时（核对者嫌薄、读者嫌长）：准确和完整听核对者的，编号列举的东西不删；读者嫌长的地方，去删重复的板块和重复的例子，不去删步骤和名目。

请它另外回答两个问题：这份东西是不是明显比读原文省事？哪些段落可以删掉而不影响理解？

处理：它复述的主旨和 `map.md` 对不上，说明成品没把主线讲出来，要重写相关章节而不是补一句总结。卡住的地方，原文里有解释的就地补一句；原文本身没解释的，不替作者补，写明「原文没有解释」，需要时把你的解释放进评注。读者没有原书，它说「看懂了」不代表内容准确，准确性只看前两道。

## 4 什么时候算完

- 机器核对退出码 0；
- 独立核对里没有未处理的「不支持」「查不到」；
- 读者复述的主旨和地图一致，卡点已处理或写明为什么不改。

同一个问题改了两轮还过不了，停下来把情况告诉用户，不要硬凑。

第二轮只查改过的句子：把改前的成稿留一份副本，用 `diff` 或逐段对比列出改动的行，连同原文一起给核对者。

**核对最多两轮。** 独立核对和读者试读各做一轮，改完后如果改动超过五句，再各做一轮只查改过的地方。第二轮之后的修改不再派人，自己把改过的句子逐句回原文对一遍，重跑机器核对，并在交付汇报里写明「第二轮之后改了多少处，未再复核」。核对是为了把错降下来，不是为了追求零意见。

## 5 交付汇报里的数字从哪来

- 引文条数与结果：`W/verify/report-all.md` 的「引文与锚」一节。
- 章节覆盖：同一份报告的「章节覆盖」表。
- 独立核对：`W/verify/independent.md` 里各判定的条数，以及你改了几条。
- 没读到或存疑的：底稿和成稿里的 `〔存疑：…〕` 标记，汇总进成稿末尾的「关于这份解析」。

照实写。没做的核对写「未做」，不写成通过。
