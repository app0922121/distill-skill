# 03 · 写精华解析（digest.md）

第 4 步读这份。写的时候手边只开 `map.md` 和 `notes/`（多份材料再加 `cross.md`）。底稿里没有的，成品里不能有；想起一个「书里好像还说过」的点，回原文找到、补进底稿，再写。

## 1 读者和目标

读者没读过这本书，也没有这个领域的背景，手里只有这一份成品。读完他应该能说出：这本书要解决什么问题、作者的答案是什么、答案靠什么站住、怎么用、在哪里不管用。想核对任何一句，顺着出处标签能回到原文。

成品要**比原文省事，又不能让读者回头去翻原文**。省掉的是铺垫和重复，不是步骤和名目。

## 2 三层怎么写

| 层 | 是什么 | 写法 |
|---|---|---|
| 原书 | 作者说的：直接引语，以及对某一处原文的忠实转述 | 正常行文，段末或要点末挂锚：`……先诊断再给方案〔p45〕。` 直接引语加引号，必须和原文一字不差 |
| 归纳 | 把几处原文合起来得出的概括。每个成分都有出处，但作者没有说过这句话 | 句首加 `【归纳】`，句末列出依据的锚：`【归纳】全书的方法可以归为三步……〔p45、p112、p203〕` |
| 评注 | 整理者自己的东西：批评、对照、应用建议、推断、对图表的猜读 | 单独成块，以 `> [评注]` 开头。不混进正文句子里 |

判断一句话属于哪层：

- 作者在某一处明确说了 → 原书。
- 作者分几处说了，你只是把它们并在一起 → 归纳。
- 成分都有出处，但**把它们连起来的那层关系**（「所以」「对应」「其实是同一件事」）是你加的 → 评注。
- 作者没说 → 评注，或者不写。

不替作者补话的几种常见越界：把作者的例子推广成普遍规律；给作者的方法补上他没写的步骤；给作者没定义的词加一句解释；把作者的推测、预计写成已经发生的事实；用别的书的概念解释这本书并写成作者的意思。发现自己在做这些，要么删，要么挪进评注块并写明是整理者的看法。

**限定词不能丢。** 「通常」「几乎」「恐怕」「如果……就」「在某种情况下」是作者意思的一部分。压缩时最先丢的就是它们，丢了，句子就从「作者这么说」变成「你替作者说了更满的话」。

**引号只给原话。** 脚本查的是 “” 「」 『』 三种引号。作者自创的短术语可以加引号，但也要是原文用词：十二个字以下的短引号脚本不查，自己对一眼。你自己拟的问句、假想的客户原话、你的概括，一律不加引号（要强调就用加粗）。脚本把引号里十二个汉字以上的内容都当引文去原文里找。

## 3 成品结构

按下面的骨架搭。板块没有材料支撑就不出；**和正文重复的板块也不出**。

主体之后的那些板块（清单、三句话、自测、数字与依据、这里没讲的）是给整本书准备的：书很长，读者需要在末尾有地方速查。材料不长（三万字以内）时，主体本身就能一眼翻完，这些板块多半只是把正文再说一遍，是成品变长的主要原因。短材料默认只出：标题两行、一屏速览、主体、关键术语、评注、关于这份解析。其余板块逐个问一句「它有没有正文里没有的东西」，有才出：比如书里数字很多且来源不一，「数字与依据」表才值得单列；正文已经按步骤写清了做法，就不要再出一份清单。

```markdown
# 《书名》精华解析

材料等级：T1（手里有原文，已通读）｜作者 · 版本｜读了全书 312 页中的 298 页，跳过致谢和索引

> 怎么读：句末的〔p45〕是出处，指所给文件的第 45 页，可以回原文核对。带【归纳】的句子是整理者把几处原文合起来的概括，原书没有这句原话。「评注」块是整理者自己的判断，不是作者的意思。

## 一屏速览
- 一句话：……
- 作者要解决的问题：……
- 核心论点（3–7 条，每条一句）
- 读完能拿来做什么：……

## （主体：按书的骨架，一个核心论点或一个部分一节）
### （论点或方法的名字）
它回答什么问题 → 作者的答案 → 靠什么站住（理由、证据、案例）→ 怎么用 → 什么时候不管用

## 关键术语
| 术语 | 作者的用法 | 和平常意思的差别 |

## 拿来就能用的清单        ← 方法类内容才有
## 评注                    ← 这本书要打什么折扣
## 如果只记三句话
## 自测                    ← 3–5 个问题
## 数字与依据              ← 书里出现了哪些数字、作者各给了什么来源（数字多时才出）
## 这里没讲的              ← 只读了一部分时：哪些东西作者留到后面才讲
## 关于这份解析            ← 写给读者看的说明
```

逐项说明：

- **标题下的两行是必需的**：材料等级那一行要带括号里的白话解释（脚本会查这一行在不在）；「怎么读」那一行按这份成品实际用到的标记来写，没用到的不提。成品要能脱离网页版单独看懂。
- **一屏速览**要让人不往下翻就知道值不值得继续看。其中「读完能拿来做什么」是整理者的判断，句首标 `【归纳】` 并挂上它所依据的那几处。它是全篇最容易走样的地方：把一节压成一句时，因果被简化、限定词被丢掉、数字被说满。**速览最后写；写完逐条回正文对应的那一节对一遍**，正文怎么限定的，速览就怎么限定。速览里的每一条都挂锚。
- **主体按书的骨架组织**，不按「能不能变成方法」来筛。论述、历史、叙事类的书，主线本身就是内容。可以调整顺序，调了就在末尾说明里写一句，并保留原书的章节名，方便对照。
- **按内容类型调整每一节的重心**：

  | 类型 | 每节的重心 | 特别注意 |
  |---|---|---|
  | 方法与实操 | 步骤、判据、适用前提、失败情形 | 步骤和数字照原书，不简化成口号 |
  | 论述与观点 | 主张、理由、证据、作者回应的反对意见 | 分清作者的结论和作者的推测 |
  | 叙事与案例 | 发生了什么、因果怎么连、作者从中得出什么 | 时间相邻不等于因果 |
  | 知识与参考 | 概念之间的关系、分类、对照表 | 多用表，少用长段 |
  | 课程与讲座 | 每讲的要点、示范、作业或练习 | 讲者的口头强调要保留 |
  | 对话与访谈 | 各方的立场、分歧点、共识 | 写清谁说的 |

- **每个核心章节都要有去向**：写进了主体，或者在 `chapters.json` 里给这一章加 `omitted_reason` 并在末尾说明里列出。脚本会查。
- **评注**只留会改变读者怎么用这本书的内容：论证薄弱处、数据没有来源、适用范围比作者说的窄、已经过时。批评要有依据：书内自相矛盾处挂书内的锚；外部批评挂网页来源的锚；纯属整理者推断的，直说是推断。可有可无的感想不写。评注里引到书里的事实，同样要准确、要挂锚。
- **图表只剩零散文字时**（OCR 或纯文本常见）：正文只写能从行文确认的部分，并说明这张图没读全。你根据零散文字猜出来的结构放进评注，写明是猜的；每张图一个短评注，列出能辨认的名目即可，不抄残字，不展开推演。
- **自测题**只问成品里答得出的内容。
- **术语表**最后一列是整理者的说明，表头写成「和平常意思的差别（整理者说明）」。对材料状况的交代（哪张图没读全、哪里有错字）放在「关于这份解析」或 `〔存疑：…〕` 里，不夹在正文句子里。
- **「关于这份解析」是写给读者的**，用白话交代：读的是哪个版本、读了多少、跳过和略去了什么及原因、材料本身的问题（OCR 错字、图表读不全）、哪些地方存疑、做过哪些核对（如「引语已逐字回查」「另有一人逐条回原文核对过转述」；没做的就写没做）。**不要出现工作区里的文件名、脚本名、流程里的行话**，读者拿不到那些东西；过程细节放在给用户的交付汇报里。
- **T2 的成品**：标题下写 `材料等级：T2（没有读到原书全文，据目录、试读章节和作者访谈整理）`。主体按目录搭骨架，没有材料的章节只列标题并写「无材料」。不出页码；方法步骤只写材料里明确有的，并说清出自哪份材料。材料里只有名字、没有解释的概念，就写「材料里只有名字」；读者不懂就读不下去的，把你的解释放进评注并写明是整理者的解释，不写成作者的定义。
- **T2、T3 的成品末尾附「材料清单」**：跑 `python3 S/prep.py sources W`，把输出的表贴在最后。成品里的 `〔W03〕` 要能在这张表里查到链接，否则读者只看 Markdown 时没法回查。
- **T2 不该比 T1 长。** 没读到正文，能写的只有骨架、主张和材料覆盖到的那几处。把配套资料、访谈逐条转述一遍不叫蒸馏；每章一小段，说清它讲什么、材料里能确认到什么程度。
- **二手材料把书说错了**（提到的概念在目录和一手材料里都找不到）：不采用，并在「关于这份解析」里点名提醒一句，免得读者在别处看到同样的说法。
- **T3 的成品**：一页。写 `材料等级：T3（只有简介、短评等二手材料）`；列出各来源一致提到的主张，逐条写「据某来源」并挂锚；最后写怎样能拿到原文、拿到后能多出什么。不出引语、术语表、清单。

## 4 出处怎么挂

- **挂在块的末尾**：一个段落、一组要点、一张表，内容出自相邻的一两页时，在段末或这组要点的引导句后挂一个范围锚就够了，如 `〔p45-47〕`。不必句句挂、行行挂。
- 一段里的内容出自相隔较远的几处时，分别挂在各自的句末。
- 直接引语、数字、专名，紧跟着挂它自己的锚。
- **能用页码就用页码。** 页码读者能拿去翻书；行号只有对着文本文件才有用。材料只有行号时，在「关于这份解析」里说明行号指的是哪份文本。
- T2、T3 没有原书兜底，每个段落、每条要点、表格每一行都要有自己的来源锚。
- 存疑标记 `〔存疑：…〕` 在正文里只留会影响读者理解的那几处，其余汇总到「关于这份解析」。

## 5 详略：先保住不能丢的，再删该删的

不设字数和比例指标。两轮实测的教训是：按比例压，会把步骤和名目压没，读者想照着做还得回原文；不压，又和原文一样长。管详略要看内容，不看百分比。

**不能丢的（颗粒度地板）**

- 作者编号或逐条列举的东西——步骤、原则、要素、标志、好处、条件——**全部列出，一条不少**。可以一行一条，可以并成一张表，但不能写成「共七条，例如其中三条」。你自己加的分类、编号、计数（「可以分成三类」「一共四步」）是归纳，要标 `【归纳】`。
- 每个步骤做什么、每个要素指什么，至少一句话说清；只剩名字等于没写。
- 图表和模型里的各个组成部分（有哪几格、哪几步、各叫什么、各对应什么）。读不全的照实说读不全。
- 数字、阈值、判据，以及作者给它们的来源（没给来源也要说没给）。
- 每个核心论点最关键的一个例子，要讲完整：谁、遇到什么、怎么做、结果。
- 适用前提、限定条件、作者自己说的不适用情形。

**可以归并的**

- 十来条以上、性质相同的清单（常见问题、症状、例句）：按类归并，并写明原文共多少条、在哪几页。归并完逐条数一遍，确认原文每一条都落进了某一类。

**该删的**

- 铺垫、过渡、重复论证、作者的自我介绍和劝说。
- 同一论点的第二、第三个例子。
- 你自己的工作过程。
- 可有可无的评注。评注和末尾说明加起来明显长过正文的五分之一，就压。

写完自查一遍：**只拿着这份成品，能不能照着做？** 把原文里所有编号列举的地方过一遍，看成品里是不是都列全了。

`verify.py` 会报成稿相当于原文的百分之几，那只是个参考数。密集的方法类短材料到原文的一半以上是正常的；整本书通常在一成上下。数字偏离很远时想一想原因，但不要为了这个数去增删内容。用户明确要「更短」或「更详细」时照用户说的，并在末尾说明里写一句。

## 6 写法

- **先用日常话说清楚，再给术语。** 术语第一次出现时，先有一句大白话说它是什么、干什么用。
- **例子要走完。** 用了书里的案例，就把「遇到什么、怎么做、结果怎样」讲完，再说它说明了什么。
- **句子之间的关系要写出来。** 转折、因果、举例，用一句话交代，不让读者猜。要点和要点之间有先后或因果的，写成连贯的段落比拆成条目好读。
- **数字、专名、步骤照原书。** 不把「三到五次」写成「多次」，不把七步并成四步。
- **不写自己的工作过程。**「本节将介绍」「经过分析我们发现」这类话删掉。
- **版面要能扫读。** 一个例子超过五六行就分段（处境、做法、结果各一段）。表格的一个格子里不要塞十几项，那样的内容改成格子外的分类列表。步骤和并列的条目用编号或列表，别挤成一整段。
- **长内容分节写。** 一次写一到两节，写完存盘再写下一节，最后通读一遍把前后说法对齐。
- 不要的写法：为了显得全面把每章平均写一段；把目录改写一遍当主体；用排比和口号收尾；给作者没有的结论加上「可见」「显然」。
